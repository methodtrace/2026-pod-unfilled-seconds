# Unfilled Seconds That Demand Cannot Recover: Duration Menus, maxseq and Live CTV Ad Pods

Code for the paper "Unfilled Seconds That Demand Cannot Recover: Duration Menus, maxseq and Live CTV Ad Pods" (Prashant Chaudhary, 2026). The paper computes the structural floor of unfilled seconds in a dynamic ad pod exactly from the duration menu, the ad cap and the break length, states seven configuration rules for it, and splits the unfilled seconds of a break into structural, demand and readiness parts.

Code: Apache-2.0. The paper's numbers, rule tables and figures in `data/analysis/`: CC BY 4.0. Copyright 2026 Prashant Chaudhary (see `NOTICE`).

## Regenerate

Python 3.9 or newer, standard library only; matplotlib for the figures only. From the repository root:

```sh
sh code/run_all.sh --tier quick --out ./run-quick
sh code/run_all.sh --tier narrow --out ./run-narrow
sh code/run_all.sh --tier full --out ./run-full --jobs 8
python3 code/analysis_rules.py --res ./run-full --out ./run-analysis/rules
python3 code/manuscript_numbers.py --full ./run-full --narrow ./run-narrow --rules ./run-analysis/rules --out ./run-analysis
python3 code/figures.py --res ./run-full --rules ./run-analysis/rules --out ./run-analysis/figures
```

Each tier runs the unit tests, then its experiments. The quick tier runs every experiment on a small grid in about a minute; the narrow tier, the seven study menus, takes about 6 minutes on 10 cores and 45 minutes on 2; the full tier, the grid every number in the paper comes from, takes about 90 minutes on 10 cores and several hours on fewer, needs about 6 GB of disk (4 GB of tables and a 2 GB unit cache), and resumes after a stop. `manuscript_numbers.py` then recomputes every number cited in the paper from the run, each with the output file it comes from, in `./run-analysis/numbers.md`; `data/analysis/numbers.md` is the same file from the release run. Result files are deterministic: adding `--check` to the quick or narrow tier compares a run with the manifests in `code/expected/` (compressed files by their decompressed bytes); on the platforms tested they match exactly, and only values that pass through the platform's math library could differ in the last bit elsewhere. Every `timing.json` records `tree_sha256`, a digest of the whole `code/` folder that produced it; for this release it is `97e25854335b5f1f916a63ddb6e29be5e5967635135db57aa34201c8ba224a48` over 83 files, and `python3 -c "import sys; sys.path.insert(0, 'code'); from podsim import registry; print(registry.tree_digest())"` recomputes it.
